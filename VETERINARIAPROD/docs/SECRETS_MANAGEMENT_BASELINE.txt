SECRETS MANAGEMENT BASELINE

1. Fuente primaria
- produccion: AWS Secrets Manager o equivalente
- fallback controlado: variables de entorno inyectadas por el runtime
- fallback operativo adicional: `VAR_FILE` o bundle JSON montado via `SECRETS_FILE`

2. Ya existe en repo
- Terraform base en `terraform/secrets.tf`
- ejemplos de variables en `.env.example` y `.env.production.example`
- resolver shared en `shared/secrets.js` con soporte `VAR`, `VAR_FILE` y `SECRETS_FILE`

3. Regla operativa
- no commitear `.env` reales
- rotar `INTERNAL_SECRET`, credenciales DB, Redis y JWT keys segun politica
- AWS Secrets Manager / Vault es la opcion recomendada para produccion, pero el runtime tambien soporta `SECRETS_FILE` y `*_FILE` para despliegues sin ese servicio.
- preferir montaje por archivo para PEMs, passwords y tokens largos cuando el runtime lo permita
- validar archivos de ejemplo / plantillas con:
  `node scripts/secrets/validate-env.js .env.production.example --allow-placeholders`

4. Secretos minimos criticos
- `DB_PASSWORD`
- `REDIS_URL` / `REDIS_PASSWORD`
- `INTERNAL_SECRET`
- `JWT_PRIVATE_KEY`
- `JWT_PUBLIC_KEY`
- `GRAFANA_PASSWORD`

5. Rotacion recomendada
- credenciales app/infra: trimestral
- secretos comprometidos: inmediata
- JWT signing key: usar `npm run secrets:jwt-rotate` para generar un nuevo par y `JWT_KEYRING_JSON` para publicar clave actual + claves verify-only durante el rolling deploy. Esperar mas que `JWT_ACCESS_EXPIRES` antes de retirar claves anteriores.
